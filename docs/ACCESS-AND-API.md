# Hak akses dan action

Semua data prototipe wajib sintetis. Shared secret server-to-server diperiksa sebelum dispatch. Sesi harus aktif dan pengguna Users harus berstatus `Actif` pada setiap action internal. Tidak ada signup publik. Administrator membuat akun lewat editor script, bukan endpoint.

| Peran                   | Perubahan yang diizinkan                                                                        |
| ----------------------- | ----------------------------------------------------------------------------------------------- |
| Publik                  | `requests.create` jika diaktifkan administrator; tidak dapat membaca daftar/detail              |
| Operator                | Membuat/memperbarui/transisi permohonan, membuat/menugaskan/transisi misi, kesiapan sumber daya |
| Koordinator medis       | Menyimpan penilaian medis, membaca catatan pasien                                               |
| Koordinator penerbangan | Menyimpan keputusan penerbangan dan checklist                                                   |
| Dokter/perawat          | Catatan pasien, checklist, serah terima                                                         |
| Rumah sakit penerima    | Serah terima                                                                                    |
| Viewer pimpinan         | Hanya agregat `leadership.summary`; tidak membaca record rinci atau melakukan perubahan         |
| Administrator           | Semua action operasional; undangan tetap dibuat melalui editor script                           |

Peran internal selain Viewer pimpinan dapat membaca tabel operasional non-klinis; PatientNotes hanya untuk dokter/perawat, koordinator medis, administrator. Tidak ada akses browser ke Users, Sessions, Settings, ProcessedOperations. Session token di-hash di server; token asli hanya dikembalikan dari Apps Script ke Vercel untuk cookie HttpOnly, Secure, SameSite=Strict selama satu jam. Token berasal dari CSPRNG Node.js 32 byte. Token tidak berada di IndexedDB, localStorage atau bundle frontend. Logout mencabut sesi server dan menghapus cookie. Login dibatasi lima percobaan per nama pengguna per jendela cache 15 menit, dengan error generik dan hash dummy untuk pengguna tak dikenal. Ini pembatasan prototipe, bukan kontrol penyalahgunaan lengkap. Pembatasan berdasarkan IP tidak diklaim.

## Envelope

Browser mengirim POST `/api/gateway`: `{action,payload}`. Function membatasi payload 32 KiB, memvalidasi Origin terhadap `APP_ORIGIN`, memeriksa allowlist action, dan memasukkan `secret`, `sessionToken`, `requestId` dalam payload server-to-server. Apps Script membatasi payload 40 KB dan tidak membaca arbitrary header.

Respons: `{ok,data?,error?:{code,message},requestId,serverTime}`. Waktu ISO UTC. Error aman, tanpa stack trace atau rahasia. Gateway tidak mengganti connected menjadi demo saat upstream gagal. Error transport dibedakan dari sukses penyimpanan.

| Action                                                                                                                                                                                        | Payload                                                                 | Hasil                                                             |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `health`                                                                                                                                                                                      | `{}`                                                                    | Status koneksi minimal, bukan data atau validasi Sheets           |
| `auth.login`                                                                                                                                                                                  | `username,password`                                                     | Actor; token ditangani Function sebagai cookie                    |
| `auth.logout`, `auth.me`                                                                                                                                                                      | `{}`                                                                    | Logout / actor sesi aktif                                         |
| `requests.create`                                                                                                                                                                             | `id,operationId,data`                                                   | Permohonan status Tercatat di Server                              |
| `requests.update`                                                                                                                                                                             | `id,operationId,baseRevision,data`                                      | Memperbarui field permohonan yang tervalidasi                     |
| `requests.list`, `missions.list`, `medicalReviews.list`, `flightReviews.list`, `patientNotes.list`, `checklists.list`, `handovers.list`, `facilities.list`, `resources.list`, `activity.list` | `offset=0,limit=50` (maks 100), `status?,search?,requestId?,missionId?` | `{items,total}` dengan filter dan pagination server               |
| `requests.get`, `missions.get`                                                                                                                                                                | `id`                                                                    | Record atau null                                                  |
| `requests.transition`, `missions.transition`                                                                                                                                                  | `id,operationId,baseRevision,status,reason?`                            | Transisi tervalidasi                                              |
| `missions.assign`                                                                                                                                                                             | `operationId,requestId,team`                                            | Misi Persiapan dengan tim dan record MissionAssignments           |
| `medicalReviews.save`                                                                                                                                                                         | `id?,operationId,baseRevision?,data:{requestId,text,status}`            | Record penilaian manual                                           |
| `flightReviews.save`                                                                                                                                                                          | `id?,operationId,baseRevision?,data:{requestId,text,status,reason?}`    | Keputusan manual; alasan wajib untuk Ditunda/Tidak Disetujui      |
| `patientNotes.create`, `checklists.save`, `handovers.save`                                                                                                                                    | `id?,operationId,baseRevision?,data:{requestId,missionId,text}`         | Record dengan relasi permohonan dan misi yang cocok               |
| `resources.update`                                                                                                                                                                            | `id,operationId,baseRevision,data:{status}`                             | Perlu konfirmasi / Siap simulasi / Tidak siap simulasi            |
| `reports.summary`                                                                                                                                                                             | `{}`                                                                    | Tabel operasional yang boleh dibaca aktor, tanpa tabel kredensial |

Semua perubahan memerlukan operationId UUID. Existing record memerlukan baseRevision yang tepat. MedicalReviews dan FlightReviews masing-masing memiliki satu record aktif per permohonan; pembaruan memakai ID dan revision record terbaru, sedangkan riwayat perubahan tetap dicatat di ActivityLogs. Percobaan membuat record penilaian kedua ditolak sebagai CONFLICT. Form menciptakan operationId sekali dan menggunakan ID sama saat retry. Permohonan hanya maju satu tahap. Misi maju satu tahap; Berangkat memerlukan keputusan penerbangan terbaru Disetujui. Penilaian medis tidak memberikan izin terbang. Selesai memerlukan serah terima yang terhubung atau alasan override oleh operator/admin. Action misi Dibatalkan memerlukan alasan. ActivityLogs mencatat perubahan status, waktu, actor, alasan dan durasi sejak perubahan sebelumnya; ini **bukan audit log tahan manipulasi**. Review merupakan catatan manual, bukan rekomendasi atau persetujuan otomatis.

## Skema Sheets dan kegagalan sebagian

Masing-masing dari 15 sheet memakai header terverifikasi: `id,createdAt,updatedAt,createdBy,updatedBy,revision,status,data`. Kolom data berisi JSON field domain dan relasi ID; ID UUID tidak bergantung nomor baris. Metadata diduplikasi dan dicek saat baca. Header yang berbeda menghentikan operasi, tidak dimigrasikan dengan menghapus data. Teks langsung diawali apostrof bila berpotensi menjadi formula; JSON disimpan sebagai literal objek dan CSV melakukan escaping formula serta quote.

Setiap operasi memakai script lock. Tabel yang dibutuhkan dibaca satu kali per dispatch dan range diakses batch. Append record dilakukan batch. Pembaruan record terpilih menulis baris terkait. Apps Script/Sheets tetap bukan database transaksional: setelah validasi, ProcessedOperations ditulis Pending dan di-flush, lalu perubahan sheet di-flush, baru journal menjadi Committed. Retry Committed mengembalikan hasil awal kepada pemilik yang sama setelah pemeriksaan peran. Pending/partial menolak retry untuk rekonsiliasi manual dan membekukan perubahan operasional baru sampai administrator menyelesaikan rekonsiliasi; pembacaan dan login tetap tersedia. Tidak mengulang perubahan yang mungkin sudah diterapkan.

Untuk rekonsiliasi: bekukan pengiriman operasi terkait, buat salinan privat spreadsheet, cari operationId di ProcessedOperations, periksa entityId/result terhadap record tujuan, assignment dan ActivityLogs. Lengkapi atau pulihkan perubahan secara manual oleh administrator yang berwenang, pertahankan ID/revision dan catat tindakan. Tandai Committed **hanya setelah semua dampak diverifikasi**. Jangan menghapus journal Pending atau membuat operationId baru untuk menyembunyikan kegagalan. Tidak tersedia recovery otomatis atau jaminan exactly-once pada kegagalan multi-sheet.

Keterbatasan skalabilitas: filter/pagination berlaku pada hasil API, tetapi scan range tabel masih dilakukan di Sheets. Laporan ringkasan mengambil tabel operasional penuh yang diizinkan, sehingga hanya cocok untuk dataset sintetis kecil. UI memiliki pagination lokal 10/25/50 baris dan reset halaman ketika filter berubah. Pengambilan data ringkasan masih penuh; indexing, pemuatan halaman dari server, granular row permissions dan agregasi laporan terukur membutuhkan pekerjaan lanjutan sebelum penggunaan nyata.

## Retry, konflik dan pembaruan versi

ProcessedOperations menyimpan fingerprint SHA-256 atas action dan payload JSON kanonik, bukan hanya ID. Menggunakan ID lama untuk payload/action lain menghasilkan OPERATION_REUSE. Urutan key JSON dan field undefined tidak mengubah fingerprint. Payload bertingkat terlalu dalam ditolak. Semua retry wajib mengirim operationId, entity ID, baseRevision dan payload yang sama. Misi baru menggunakan entity ID dari operasi agar journal dan outbox dapat merujuk objek yang sama.

Outbox disimpan berurutan memakai sequence IndexedDB, dipisah menurut mode dan pemilik. Penambahan operasi baru tidak mendahului antrean lama. Retry connected memeriksa sesi aktif dan identitas pengguna; sesi yang ditolak server memicu login ulang. Konflik, validasi/izin/alur yang ditolak, dan partial failure menghentikan antrean, bukan dilewati. Konflik/penolakan dapat diarsipkan setelah ditinjau, dengan salinan lokal yang dapat diunduh dari halaman Outbox. Partial failure tidak dapat diarsipkan untuk melewati rekonsiliasi server. Arsip tidak membatalkan perubahan server dan tidak dikirim ulang.

Draft internal menyimpan field dan revision yang ditinjau, terpisah per mode, pengguna, permohonan dan formulir. Polling tidak menimpa draft; jika penilaian server berubah, petugas dapat memuat versi terbaru secara eksplisit. PDF menampilkan durasi tahap pada record aktivitas yang memiliki durationSeconds; bukan KPI resmi.

Saat beralih dari versi awal: tutup semua tab aplikasi lama sebelum membuka versi baru agar upgrade IndexedDB dapat selesai. Store lama tidak dihapus, tetapi draft/outbox tanpa namespace mode tidak dikirim atau dipindah otomatis karena mode asalnya tidak dapat dibuktikan. Backup dan tinjau secara manual sebelum migrasi. Journal server lama tanpa fingerprint tetap dipertahankan; replay ditolak sampai administrator meninjau operasi. Jangan mengarang fingerprint atau menghapus journal agar retry lolos. History review lama tetap dibaca, tetapi record terakhir menjadi record aktif untuk pembaruan berikutnya. Deploy Domain.gs, Services.gs, Code.gs, dan frontend sebagai perubahan versi yang terkoordinasi.

## Pengawasan pimpinan

`leadership.summary` menerima payload `{period: "all" | "7" | "30"}` dan hanya dapat dipanggil Viewer pimpinan atau Administrator. Tanpa sesi aktif ditolak; peran lain ditolak. Viewer tidak lagi dapat memanggil `reports.summary`, daftar/detail record, atau mutasi. Login Viewer dari website diarahkan ke `/pimpinan`; `/internal` dan modul operasional mobile mengarahkannya ke dashboard pimpinan. Administrator tetap memiliki akses operasional sesuai matriks.

Respons hanya memuat angka agregat, status dari allowlist, tanggal yang dinormalisasi, distribusi tahapan, tren harian, sampel durasi, dan temuan kualitas data. Tidak ada ID record, identitas/kontak pemohon, koordinat, nama fasilitas/tim, teks penilaian, alasan bebas atau catatan pasien. Apps Script membaca delapan tabel operasional yang dibutuhkan satu kali per dispatch, tanpa membaca PatientNotes/Checklists/ProcessedOperations. Autentikasi tetap membaca Users/Sessions untuk memverifikasi sesi. Respons tidak memuat tabel mentah dan action tidak menulis journal atau data.

Periode 7/30 berarti kohor dibuat sejak pukul 00:00 UTC pada hari kalender pertama sampai waktu server saat ini. Snapshot kesiapan fasilitas/sumber daya dan kualitas data tetap memakai seluruh data. Misi aktif di luar kohor dilaporkan terpisah. Tren permohonan memakai createdAt; selesai/dibatalkan memakai updatedAt misi terminal. Tahapan yang tidak dikenal tidak dihitung sebagai misi aktif; temuan kualitas data ditampilkan. Durasi adalah rerata sampel transisi tercatat, bukan SLA/ETA atau target resmi. Indikator perhatian dapat saling tumpang tindih dan tidak boleh dijumlahkan sebagai kasus unik.

Pilihan Kasau, Kemenhan, Kemenkes dan Presiden adalah sudut tampilan simulasi atas agregat yang sama, bukan role autentikasi atau identitas pejabat. Pilihan tidak diberikan kepada server sebagai peningkatan hak akses. Ekspor CSV/PDF hanya memakai respons agregat tersebut. Tidak ada alur persetujuan/penugasan/perubahan status pada dashboard. Polling 60 detik memakai aturan visibility/offline/backoff yang sama, dan ekspor dinonaktifkan ketika refresh gagal agar data lama tidak diklaim mutakhir.

Untuk pembaruan deployment: rebuild Domain.gs, perbarui Services.gs dan Validation.gs bersama frontend/gateway. Role Viewer yang sudah ada tetap digunakan tanpa secret atau perubahan skema baru. Frontend lama tidak dapat lagi membaca data rinci memakai Viewer; perbarui link ke `/pimpinan` ketika merilis. Backend masih memindai range tabel di Sheets untuk agregasi, sehingga skala besar/kuota harus diuji terpisah.
